# 13. Security

This chapter summarizes the system's security posture: how the network is locked down, how admin actions are authenticated, where secrets live, how instances and operators are hardened, and the residual risks that are accepted by design.

## Network posture

| Control | Detail |
|---|---|
| **Port 8080 — ALB only** | The RocksDB service port is reachable **only from the ALB security group**, via a security-group reference (not an open CIDR). Clients never hit a node's `:8080` directly. |
| **SSH closed** | Port 22 is **closed to the internet**. Operators reach instances through **SSM Session Manager**; an optional break-glass CIDR can be opened via the `admin_ssh_cidr` CDK context. |
| **Cluster traffic self-scoped** | Corosync/cluster traffic is restricted to **fellow cluster members** via a self-referencing security-group rule, not the whole `10.0.0.0/16` VPC CIDR. |
| **ALB is internet-facing, HTTP only** | The ALB serves load-balanced reads on port 80. It is a **read-only data plane**: it returns **HTTP 403 for any `/admin/*` path** *and* for the writer-only mutating endpoints (`/put`, `/batch-put`, `/delete`, `/flush`), so neither admin actions nor writes are ever reachable through the public load balancer. Only `/get`, `/scan`, and `/health` are served. |

Before/after, in short: the security group went from SSH(22) and REST(8080) open to `0.0.0.0/0` plus all-traffic from the whole VPC CIDR, to 8080 ALB-only, SSH closed (SSM instead), and cluster traffic scoped to members.

## Authentication

- **Admin endpoints require a bearer token.** All `/admin/*` REST endpoints (`promote`, `demote`, `bootstrap`, `resetdb`, `leave-cluster`, `start-watcher`, `dbsize`) require an `Authorization: Bearer <token>` header. The C++ service verifies it with a **constant-time compare** and **fails closed** — any `/admin/*` request is rejected with `403` if no token is configured or the token doesn't match.
- **Token source.** The token is a 32-byte random secret generated by the first node and stored in SSM Parameter Store as a SecureString at `/rocksdb-cluster/admin-token`. Each node reads it on boot into `/etc/rocksdb/service.env` as `ADMIN_TOKEN`, so the secret never leaves the instance — tooling invokes `/admin/*` on-box via SSM using the node's own copy.
- **Input validation on `/admin/bootstrap`.** The request-body fields (`priv_ip`, `instance_id`, `region`, `volume_id`, `cluster_name`) are validated (only `[A-Za-z0-9._-]`, length-capped) before being used in a shell script, closing an unauthenticated shell-injection (RCE) vector.
- **Cluster-info endpoints are token-gated too.** `/cluster/nodes` and `/cluster/nodeids` (which expose internal private IPs and Corosync node IDs) require the same `Authorization: Bearer <token>` header as `/admin/*` and fail closed with `403`. Operator tooling (TUI, test harness) supplies the on-box token automatically.
- **HTTP request hardening.** The server validates `Content-Length` (non-numeric → `400`), caps total request size at 64 MiB (`413` beyond it), caps `/batch-put` at 1,000 pairs (`400` beyond it), and wraps every connection in a `try/catch` so a malformed request can never crash the process. `/scan` is **bounded** (`limit` default 1,000 / max 10,000 plus an `after` cursor), so it can't be used for an unbounded full-table dump.
- **Data plane is unauthenticated, and read-only through the ALB.** `/health` and the read endpoints (`/get`, `/scan`) are **not** token-gated and are reachable through the ALB. The write endpoints (`/put`, `/delete`, `/batch-put`, `/flush`) are also unauthenticated, but the **ALB blocks them with `403`**, so they're only reachable on-box (SSM → writer); a write can never be driven through the public load balancer. This is an accepted residual risk for the locked-down, in-VPC network (see below).

## Secrets

All cluster secrets live in **SSM Parameter Store as SecureStrings** (KMS-encrypted): the Corosync and Pacemaker auth keys, the `hacluster` password, and the admin token. Because these are created by instances at boot (not by CloudFormation), `cdk destroy` alone would leave them behind — so **`destroy.sh` explicitly deletes** `/rocksdb-cluster/{corosync-authkey, pacemaker-authkey, hacluster-password, admin-token, writer-instance-id}` on teardown, leaving no lingering secrets. See the [SSM Parameters table](12-api-reference.md#ssm-parameters).

## Data protection

| Control | Detail |
|---|---|
| **EBS encryption at rest** | The io2 Multi-Attach data volume is created with `encrypted=True` (account-default EBS KMS key), so the single shared copy of the dataset is encrypted at rest. Encryption can't be enabled in place — it applies on a fresh deploy. |
| **Least-privilege IAM** | The instance role's inline policy is scoped: SSM to `/rocksdb-cluster/*` parameters, `kms:Decrypt`/`GenerateDataKey` only `via ssm` (condition), and EC2 mutations to `instance/*`+`volume/*` in this account/region. Only the `autoscaling:*` actions remain `resources="*"` (the ASG ARN is created after the role, and `Describe*` needs `*`). |
| **Audit / access logs** | The ALB writes **access logs to a dedicated S3 bucket** (request-level trail: source IP, path, status). The service also logs each request (client IP · method · path · status) to journald. This is the accountability layer for the otherwise-unauthenticated data plane. |

## Instance security

| Control | Detail |
|---|---|
| **IMDSv2 enforced** | The launch template requires IMDSv2 and sets `http_put_response_hop_limit=1`, mitigating SSRF-based credential theft. |
| **No surprise reboots** | The AMI is hardened to disable `unattended-upgrades` and automatic reboots, so a node never reboots mid-cluster and looks like a failure (see [Components](06-components.md#the-ami-build-pipeline) and [Troubleshooting](11-troubleshooting.md)). |
| **SSM agent** | The instance role attaches `AmazonSSMManagedInstanceCore` so the agent registers and operators can use Session Manager / Run Command. |

## Operator access

There is **no SSH key to manage**. All operator access — the TUI, the test harness, recovery scripts, and the stress-test tooling — goes through **SSM**: Session Manager for interactive shells and Run Command for driving each node's service at `http://localhost:8080`. Node-specific actions (read a specific node, promote, kill) target the instance by instance-id; kill/scale use the EC2/ASG APIs. Load-balanced reads go through the ALB on port 80 — including the TUI's node-agnostic `read <key>` and bare `scan`, which call the ALB directly (a real HTTP client) rather than going through SSM.

## Accepted residual risks

| Risk | Status / compensating controls |
|---|---|
| **No TLS / plaintext HTTP** | There is no public domain or certificate available (a publicly-trusted ACM cert requires a domain), so traffic to the ALB (port 80) and ALB→node is plaintext HTTP. **Compensating controls:** the security group restricts 8080 to the ALB, the ALB blocks `/admin/*` and all write endpoints, and traffic stays in-VPC. **Future options to add TLS:** import a self-signed cert to ACM, front with CloudFront (`*.cloudfront.net` managed cert), or register a domain for ACM DNS validation. |
| **Unauthenticated data plane** | `/get` and `/scan` are not token-gated. Accepted because the network is locked down (8080 ALB-only, in-VPC). The **write endpoints are blocked at the ALB** (read-only public plane) and are role-enforced to the writer, so mutations can't be driven through the LB; add token/mTLS or an authenticating proxy if even reads are sensitive. (`/scan` is bounded and `/cluster/*` is now token-gated.) |
| **Volumetric DoS (no WAF / no rate limit)** | The ALB is internet-facing with an unauthenticated data plane and **no WAF or per-IP rate limit**. A rate-based WAF was evaluated and **removed**: the demo's load/stress tests deliberately flood the ALB from a few loader IPs, which a per-IP rule blocks (it killed a stress run during testing). Accepted for the demo; offset by in-VPC + ALB-only `:8080` + bounded `/scan` + HTTP request caps. **Re-add a WAF or IP allow-list before non-demo/production use.** |
| **Single AZ / single volume / single writer** | The core architectural trade-offs (no multi-AZ resilience, one shared failure domain, one writer) remain as documented in the [Overview](01-overview.md#when-to-use-this-and-when-not-to). |
